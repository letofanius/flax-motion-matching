# MotionMatching plugin (0.1.0)

Standalone Flax Engine plugin that adds data-driven pose-search motion
matching to any host project. The host owns the character, the input, and
all locomotion decisions. The plugin owns the animation database, the pose
search, and the playback session behind one neutral input/output contract.

- Runtime: pose search, query filters, policy, playback, sampler, trace,
  trajectory math, schema, database, and baker (`Source/MotionMatching`).
- Host shell: `MotionMatchingController` plus the input DTOs in
  `MotionMatchingInputContract.cs` (`Source/MotionMatching`).
- Editor: registry import/export, bake, validation, audit, tuning windows,
  and contract tests (`Source/MotionMatchingEditor`).
- No locomotion policy ships here. Gait, scope, and intent decisions live
  in the host input provider.

## Requirements

- Flax Engine 1.12 (`MinEngineVersion` 1.12.6912, see
  `MotionMatching.flaxproj`). The plugin project references only
  `$(EnginePath)/Flax.flaxproj` and never a host project.
- .NET 10 (`net10.0`, C# 14) for the script assemblies, as generated by
  Flax 1.12 targets.
- Python 3.10+ (standard library only) for the offline contract gate.
  No Flax installation, database, or editor is needed for the gate.

`*.csproj` files keep the Flax configuration blocks (per-configuration
`PropertyGroup` entries, engine `Reference` hint paths, and the explicit
`Compile` list for checked-in C# sources). Machine-local generated entries
are intentionally absent: Flax regenerates `*.Gen.cs` and
`*.Bindings.Gen.cs` on load. There is no checked-in host integration
module and no bundled host content.

## 5-minute quickstart

These steps assume an existing Flax 1.12 host project that will consume
this plugin as a referenced project.

### 1. Reference the plugin project

In the host `.flaxproj`, add a project reference next to the engine
reference:

```json
"References": [
    { "Name": "$(EnginePath)/Flax.flaxproj" },
    { "Name": "$(ProjectPath)/Plugins/MotionMatching/MotionMatching.flaxproj" }
]
```

Copy or clone this repository under the host `Plugins/MotionMatching`
folder so the relative path above resolves, then reopen the host project
so Flax generates bindings.

### 2. Add the target modules

Game target (host `*Target.Build.cs`):

```csharp
Modules.Add("MotionMatching");
```

Editor target (host `*EditorTarget.Build.cs`, only when bake, registry,
tuning, or contract-test tooling is needed):

```csharp
Modules.Add("MotionMatching");
Modules.Add("MotionMatchingEditor");
```

The runtime module never depends on the editor module. The editor module
declares `options.PublicDependencies.Add("MotionMatching")`.

### 3. Author a schema for the host rig

Create a `PoseSearchSchema` for the consuming rig before baking. The
skeleton profile ships empty on purpose: set `Skeleton.Root`,
`Skeleton.Pelvis`, `Skeleton.LeftFoot`, and `Skeleton.RightFoot` to the
host bone names (scene to `MotionMatchingController` to `Schema` to
`Skeleton`). Optional names (`Spine`, `Head`, `LeftHand`, `RightHand`)
are stored for future channels. Keep the six default
`TrajectorySampleTimes` (`-0.4, -0.2, 0.0, 0.2, 0.4, 0.6`) unless the
host predictor is retuned to match. Full field reference is in
[Authoring](docs/AUTHORING.md) and the binding contract in [Public contract](docs/PLUGIN_CONTRACT.md).

### 4. Implement the host input provider

Implement `IMotionMatchingInputProvider` in the host. The provider owns
gameplay interpretation and produces exactly one
`MotionMatchingFrameInput` per tick:

```csharp
public sealed class HostMotionMatchingProvider : IMotionMatchingInputProvider
{
    public MotionMatchingFrameInput BuildInput(MotionMatchingInputContext ctx)
    {
        // ctx carries ActorWorld, DeltaTime, FrameId, DatabaseTags, SampleTimes.
        // 1. Advance the host trajectory predictor from actor state.
        // 2. Derive scope (AllowedTagSet / ExcludedTagSet, '+'-joined).
        // 3. Derive caller filter (LoopFilter, CandidateBand, QueryYawRate,
        //    CallerPlanarSpeed). Empty AllowedTagSet means explicit no-match.
        return new MotionMatchingFrameInput
        {
            Points = predictedPoints,       // TrajectoryPoint[], 1:1 with ctx.SampleTimes
            AllowedTagSet = includeScope,
            ExcludedTagSet = excludeScope,
            LoopFilter = 0,                 // MotionLoopFilter: 0 Any, 1 LoopOnly, 2 OneShotOnly
            CandidateBand = 0,              // 0 Any, 1 Walk, 2 Run, 3 Sprint
            QueryYawRate = 0.0f,
            CallerPlanarSpeed = 0.0f,
        };
    }

    public void Reset()
    {
        // Snap scope hysteresis and reseed the predictor (lazy on next BuildInput).
    }
}
```

`MotionMatchingController` has no provider slot and never calls
`BuildInput` or `Reset` itself. The host calls the provider, then passes
the frame to the controller. `TrajectoryPoint.Position` and `Facing` are
character-local samples interpreted through the schema root axes.

### 5. Bake the database with the editor service

Register clips with tags and loop flags, export or import the registry
JSON, then bake and validate (all in `MotionMatchingEditorService`):

```csharp
MotionMatchingEditorService.AddClipFiles(controller, new[] { "walk" }, new[] { clipPath }, loop: true);
MotionMatchingEditorService.ExportClipRegistry(controller, registryPath);
MotionMatchingEditorService.ImportClipRegistry(controller, registryPath, new ClipRegistryImportOptions());
MotionMatchingEditorService.BakeDatabase(controller);
MotionMatchingEditorService.ValidatePersistence(controller);
MotionMatchingEditorService.GenerateClipAudit(controller);  // explicit, writes Cache/MMClipAudit.txt
```

`BakeValidateAndTest` runs bake, persistence validation, and the
editor-only search self-test in one call. `QueryTopCandidates` ranks
candidates for the current trace entry without playing.

### 6. Drive the controller from the host facade

`MotionMatchingController` is a plain C# object, not a scene script.
Retain one instance in the host facade:

```csharp
var controller = new MotionMatchingController
{
    Schema = hostSchema,
    PlayerModel = hostModel,          // SkinnedModel
    CharacterBody = hostAnimatedModel, // AnimatedModel, must have no competing AnimGraph output
    DatabasePath = "MotionMatching/MyDatabase.flax",
};
controller.Initialize();
```

Per tick:

```csharp
MotionMatchingInputContext context = BuildContext(); // ActorWorld, DeltaTime, FrameId, DatabaseTags, SampleTimes
MotionMatchingFrameInput frame = provider.BuildInput(context);
controller.Update(deltaTime, actorWorldTransform, frame);
```

Teleport or respawn:

```csharp
provider.Reset();
controller.ResetPlayback();
```

Disable or destroy:

```csharp
controller.Shutdown(); // idempotent; configuration stays reusable
```

Read the current pose with `TryGetBasePose` (allocating) or
`TryGetBasePoseInto` (reusable buffer), apply host layers or IK, then
write the final pose. `Playback` and `Trace` are borrowed handles:
never destroy them, and reacquire after reset, rebind, or shutdown.
The `CharacterBody` must not run an AnimGraph that overwrites manually
written poses. Full lifecycle detail is in [Lifecycle](docs/LIFECYCLE.md).

## Offline contract gate

From this plugin directory, with Python 3.10+ (standard library only):

```text
python Tools/check_contract.py
python Tools/test_contract_audit.py
```

The [gate](Tools/check_contract.py) checks the documented public surface,
filter and recovery source invariants, asset identity, project-coupling
boundaries, the absence of any bundled host integration content, and that
every relative Markdown link inside `docs/` resolves. The [audit
tests](Tools/test_contract_audit.py) inject in-memory regressions to prove
the gate rejects them. Neither command needs a host project, assets,
generated bindings, an editor, or a bridge; paths resolve relative to the
script. These are static checks, not a native build or playback test.

## Asset identity note

The serialized binary database identity is frozen for compatibility:

```text
Game.MotionMatchingDatabase
```

Keep this `TypeName` when moving the plugin between host projects. Do
not rewrite database JSON, scene text, or asset headers to a new name;
that would orphan existing baked assets. The plugin scripting namespace
is `MotionMatching`; the legacy key is only the binary asset factory
key. See [Migration](docs/MIGRATION.md).
